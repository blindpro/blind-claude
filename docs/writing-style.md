# Writing accessible docs

Everything in this project is written to be read with a screen reader. These rules apply to documentation, code comments meant for users, command output and commit messages.

## Rules

1. Use headings to give structure. Screen readers can jump between them.
2. Use numbered or plain lists instead of tables. Tables are hard to follow by ear.
3. Do not use emoji, decorative symbols, arrows, check marks or box drawing characters.
4. Say what a link is in its text. Write "the speech document", not "click here".
5. Keep sentences short. Put the important part first.
6. Spell out symbols when they matter. Write "greater than" rather than relying on a sign in the middle of a sentence. Code in backticks is the exception, since it must be exact.
7. Do not use ASCII art or diagrams made of characters. Describe the flow in words or as a numbered list of steps.
8. Messages the mod prints or speaks should make sense on their own, without seeing what came before.
